# Open-source reuse for the browser agent

Researched October 22, 2026, before implementation of the automatic-agent iteration. This supplements [REUSE.md](REUSE.md), which covers the existing manual release. These are source/documentation and package-metadata findings, not successful ReEntry integration tests. No candidate dependency was installed during this research.

Implementation follow-up, October 23: Phase 0 subsequently adopted the selected controller/runtime/checkpointer and pinned shop, with actual evidence recorded in [AGENT_FOUNDATION.md](AGENT_FOUNDATION.md). The research snapshot below remains historical; alternatives were not all installed.

## Recommended decision

Keep ReEntry and its WXT extension. Prefer LangGraph.js with its existing SQLite checkpointer for durable orchestration. Evaluate Page Agent's separately published page controller as the browser reader. Reuse the existing model transports and official shadcn UI. Use Sauce Labs' existing shop for the commerce sandbox and Northstar for changed application requirements.

The initial stack is:

`WXT observer → adapted page context → ReEntry model interface → LangGraph + SQLite → ReEntry tasks → Chrome companion/reminders`

The extension still needs permission handling, observation triggers, a bounded delivery queue and authenticated connection. The libraries below save substantial infrastructure work; none of the reviewed products documents the complete passive task-discovery and evidence-backed completion behavior ReEntry needs.

## Page reader: promising, with concrete adaptation needed

Inspection of the [controller](https://github.com/alibaba/page-agent/blob/main/packages/page-controller/src/PageController.ts), [DOM pipeline](https://github.com/alibaba/page-agent/blob/main/packages/page-controller/src/dom/index.ts) and [React patch](https://github.com/alibaba/page-agent/blob/main/packages/page-controller/src/patches/react.ts) found:

- `getBrowserState()` refreshes the DOM tree and returns URL, title and simplified content.
- Default serialized attributes include `value`; `includeAttributes` adds to those defaults. Passing an empty list is not a verified way to exclude form values. Redaction must happen before persistence, delivery or model calls and cover visible text/URLs as well as attributes.
- The controller marks some React roots, and extraction enables highlighting with configurable opacity. Setting an operation mask off does not prove a mutation-free observer. Test page behavior, focus, overlays and self-induced mutation loops.
- The controller exposes action methods too. ReEntry should expose only its observation adapter to the agent at this stage.

First test the pinned package on synthetic Northstar and commerce pages. If the public API cannot meet data minimization and quiet-operation requirements, reuse a small licensed extraction module through a documented adaptation, or test another established reader. Record the concrete failure before deciding to write a new DOM engine. Never put NVIDIA keys into an injected demo script or use the project's free demo inference endpoint for user browsing.

## What we still build

ReEntry's contribution is the connection between browser activity and unfinished work:

- Infer tentative intent, distinguish researching from buying and group related tabs correctly.
- Define an inspectable finish condition and update evidence-linked checkpoints.
- Distinguish saving, attempting, failing and actually completing the matching task.
- Preserve corrections, reject stale updates, handle deletion and prevent replayed effects.
- Apply a calm interruption/reminder policy and compose the companion/home experience.

Keep existing NVIDIA/Ollama transports model-independent. OpenAI-compatible transport is not proof of tool-calling or structured-output reliability for every model; test the new decision contract on actual configured models. No provider replacement is necessary merely to adopt the runtime.

Use Chrome's existing side-panel, alarms and notification APIs for those platform capabilities. They are browser APIs, not additional npm scheduling frameworks. Keep the existing WXT, shadcn, Playwright, MSW and axe integrations.

## Adoption gates before feature work

1. Build the calm labelled prototype from official registry components alongside the working manual release.
2. Test Page Controller in the actual WXT content-script environment: useful page context, seeded sensitive fields, no exposed values in stored/sent data, stable focus/page behavior, bounded changes, bundle/CSP compatibility and no provider credentials in browser assets.
3. Test a LangGraph workflow with a file-backed SQLite checkpointer: branch, interrupt, terminate the process, resume in a second process, preserve task identity and avoid replaying an accepted effect. Check the Node 22/native dependency and Next production build path.
4. Establish an authenticated extension/server contract and a single task-state authority. A graph checkpoint and a task mutation must have an explicit replay/reconciliation design; using SQLite for both does not automatically make them atomic.
5. Pin proven dependencies/fixtures, retain upstream notices and record actual test evidence. Then implement automatic observation and task inference.

Registry metadata observed during research: `@page-agent/page-controller` 1.12.4, `@langchain/langgraph` 1.5.2 and `@langchain/langgraph-checkpoint-sqlite` 1.1.0. The checkpointer depends on `better-sqlite3`; package publication and declared engine support are not runtime compatibility results. Resolve compatible peers and inspect the installed release's documentation during the spike.

No restart, browser-reader, NVIDIA tool-loop or sandbox integration acceptance is marked passed by this report.
