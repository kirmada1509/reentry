# Automatic entry points and assignment tracking

October 24, 2026. This updates the agent preview; the historical manual release remains accessible. The normal app home redirects to `/observe`, and the extension toolbar opens the automatic companion. Old capture-page bookmarks redirect there too. Selected-text capture and the checkpoint form are optional **Manual tools**, with the library at `/checkpoints`. Existing captures, task history and IndexedDB data are preserved. Old `/?capture=<id>` bookmarks still open their manual checkpoint flow.

## Use on an assignment page

1. Run `./start.sh`. Reload the unpacked extension in Chrome/Brave's extension settings, then refresh existing ReEntry/source tabs. Rebuilding cannot replace an already loaded extension worker.
2. Open http://127.0.0.1:3000 and connect the browser if needed. In the companion, enable the exact site origin, for example `https://nalanda.bits-pilani.ac.in`, and grant its browser permission. The toolbar pre-fills the current site's origin; it does not silently grant access. **Browser settings** exposes configuration. All-sites access remains optional.
3. Separately allow automatic processing by the displayed model and choose **Enable task understanding**. NVIDIA receives bounded observed page text only with that agreement. The key stays on the local server.
4. Return to the actual assignment tab. With observation and inference enabled, merely opening a pending assignment can produce a task, proposed finish condition, progress checkpoint and next action. No selection or checkpoint form is needed. Inference can take several seconds; unavailable/invalid decisions remain visible and are not silently retried.
5. Continue working normally. **No submissions have been made yet** stays pending. **Draft (not submitted)** stays unfinished. A fresh, matching **Submission status → Submitted for grading** after observed pending/draft work can finish the task. **Not graded** does not mean unsubmitted. A submit click or saved draft alone never proves completion. ReEntry does not upload or submit the assignment.

## Identity and completion boundaries

The existing Page Controller reader, durable LangGraph harness and provider-independent model interface are reused. Prompt `agent-3.7` recognises assignments with a supported submission-status table plus other concrete unfinished web work (`intent: work`), alongside shopping/applications/research. Ordinary information browsing need not create a task. Other-work tasks require user completion; they do not inherit shopping or assignment success checks. Website coverage remains a preview, not a promise to understand every page.

Moodle-style `/mod/assign/view.php?id=<positive numeric id>` links retain only that numeric identifier locally. Other query parameters, including `sesskey`, and fragments are excluded. Both the observer and the extension worker derive the same page digest from that canonical identity; the worker binds it to Chrome's current tab URL. The return-link heartbeat and server independently validate the same digest. Raw URLs/IDs are not added to model context. Invalid, missing or duplicate assignment IDs are rejected safely. Earlier path-only assignment return links become unavailable until an identifiable page is revisited; their tasks/history are retained.

Assignment tasks receive a host-owned resource key. Tasks with different assignment IDs are separated before inference, even when their names match. The model cannot set that key. Completion requires the original pending/draft label-value evidence and a later submitted label-value on that same resource and browser stream/session. Existing freshness, replay, correction and receipt checks remain. First-seen already-submitted assignments are ignored by the host before inference and create no new obligation. Corrected tasks require user review. DOM text remains untrusted observed evidence, not a signed receipt from the learning platform.

## Reproduce verification

- `pnpm check`: schema, host completion/identity/restart/legacy-link tests and the existing suite.
- `REENTRY_TEST_PRODUCTION=1 pnpm test:e2e`: real unpacked extension and production app with a deterministic model transport. `agent-assignments.spec.ts` covers normal toolbar/home, stale capture bookmarks, actual DOM reading, automatic assignment creation, draft versus submission, distinct IDs, and token-free return links. Existing manual capture tests now explicitly enter **Manual tools** through the real toolbar.
- `node --conditions=react-server --import tsx scripts/evaluate-agent-assignments.ts <fresh-ignored-output.json>`: five fictional-only cases: four against the configured real model and a first-seen submitted case ignored by the host without inference. Pacing defaults to one minute between cases; an optional third argument sets 0–60000 milliseconds. Uses a disposable database, attempts each once, preserves failures/responses, and never reads the user's actual course. This is model evaluation, separate from the deterministic browser journey.

Final verification: 194 unit/integration tests, 67 production browser passes (three intentional skips), final affected journeys and commerce passes, and real NVIDIA 9/9 progress plus 5/5 assignment outcomes. Failed development trials and remaining gates are recorded in [TEST_RESULTS.md](TEST_RESULTS.md). Native VoiceOver, native permission-dialog acceptance and actual private Nalanda browsing remain unverified. No live coursework was submitted for verification.
