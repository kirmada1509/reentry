# Automatic-agent Phase 1: observe chosen sites

Implemented October 23, 2026 (IST). This is the real observation connection, separate from the fictional `/preview` and the released manual checkpoint journey. Task discovery, model reasoning and automatic completion are Phase 2 onward. No observations are sent to NVIDIA or Ollama in this phase.

## Try it

1. Start the app with `./start.sh`. Reload the unpacked ReEntry extension at `chrome://extensions` after this update; keep its existing profile and ID. The build remains at `extension/.output/chrome-mv3`.
2. Open http://127.0.0.1:3000/observe and choose **Connect browser**. In the extension tab, choose **Connect to local app**. Pairing expires after two minutes; start again from the app if needed. Connecting a different profile replaces the previous pairing.
3. Enter the exact site origin, for example `http://127.0.0.1:4176`, without `/instructions.html`. Review the local-processing statement, check its box and choose **Enable observation**. Chrome asks for additional host access when needed. All normal websites is an explicit alternative, off by default. ReEntry always excludes its own app origin.
4. Browse the enabled site normally. Selection and the manual task form are unnecessary. The app shows recent observations, and **Inspect observed evidence** shows what was retained. Whether a field is filled is recorded; its answer is not a field in the event schema. A submit attempt is explicitly unverified.
5. Open the native companion with Command+Shift+U on Mac or Ctrl+Shift+U elsewhere. Chrome's extension shortcut settings can change this. The app's **Open companion** opens the same controls in an extension tab. The existing toolbar capture action is preserved.
6. Pause in the companion or app. Resume from the companion. Change site access there to replace the session. **Disconnect and clear observations** in the app revokes the device and removes observed text; manual checkpoints are independent.

The server must keep running, but the app tab and companion may close. When the app is unreachable, the extension buffers updates and retries every minute, on new observations and when the companion opens/retries. Closing the browser stops observation; reopening it restores the permitted registration and pending buffer. Retry is bounded by the queue and retention window, rather than by a silent success message.

## Connection and data boundaries

- One-use random pairing challenge, delivered only from the configured app's exact origin/port through the existing validated extension bridge. The extension requires an explicit Connect action to exchange it.
- A separate random device bearer is stored only in extension local storage. SQLite stores its hash, the bound extension ID and active session. Provider credentials are unrelated and stay server-side. Privileged Chrome worker requests can omit `Origin`; the server requires the bound bearer and extension/device headers in that case. If an Origin is present it must be the configured extension. Website preflights cannot impersonate it. Actual production Chromium pairing and delivery exercise this boundary.
- The incoming Host must match the configured local app; forwarded host headers are not trusted. Web controls additionally require the exact Origin or same-origin fetch metadata and a custom request header. This is a single-user loopback prototype, not account authentication for a hosted service.
- Content scripts register only after site/session consent. Chrome grants host patterns across ports; the worker separately enforces exact origins, top-frame sender identity, current tab path, session and page-path digest before accepting events. A scope change or resume creates a new session ID. Paused/revoked/stale sessions cannot deliver old evidence.
- The patched Page Controller runs passively, with no browser action tools. It excludes password/payment/hidden/private/editor subtrees and filters serialized attributes. The wrapper also removes echoes of current entered answers from text/title; field labels are redacted too. This is tested minimization, not perfect removal of arbitrary personal information from page text. Embedded frames and some layouts/large pages are unsupported.
- Events retain origin, a hashed pathname, bounded title/text, ordinary field labels and filled/empty booleans, reason/time and random IDs. There is no raw page URL or form-answer field in metadata; ordinary visible text can still contain URLs or personal information. Semantic mutations are coalesced, repeated snapshots are deduplicated, and known timer/reader/UI noise is ignored. Non-landmark React apps use a root/body fallback. Background documents wait until visible before extraction.
- A single validated extension storage record holds settings and a maximum 100 queued events / 1 MB. Queue acknowledgement follows the storage write. Capacity loss, expiry, replaced sessions and unavailable storage are visible. A failed write halts reading in the current worker, and does not advance the snapshot fingerprint. A failed pause write cannot promise persistence across a worker restart; revoke site access in Chrome if storage cannot be repaired.
- The local SQLite database defaults to ignored `.runtime/agent.sqlite`, configurable through `REENTRY_AGENT_DB`. WAL and busy timeout support local request concurrency. Accepted event bodies and dedup receipts commit in one transaction. Same ID/same payload returns the committed acknowledgement; changed content under that ID is rejected. No observation text, bearer, challenge or site URL is logged by the routes.
- Observed text is pruned on access/delivery/status reconciliation after 24 hours from capture, with at most 1,000 bodies. Offline delivery does not restart that clock. Queue expiry runs before connection attempts, including during outages. A stopped server/browser cannot run pruning until reopened. Delivery rejects events older than 24 hours or more than one minute in the future. Minimal dedup receipts last 48 hours, with a 100,000-receipt capacity guard. Revoked device hashes/IDs remain so late requests fail. Clear removes logical observed bodies; it is not forensic secure erasure, an encrypted vault or a backup.

## Verification

Focused acceptance uses the real production web build and unpacked Chromium extension, actual pairing/Chrome APIs and isolated temporary SQLite files. It covers automatic navigation/form/status/submit observations, seeded sensitive exclusions, mutation coalescing, closing the app tab, actual offline delivery/full browser restart, exact-port isolation, untrusted external bridge requests, failed extension writes/recovery, a seeded full-queue boundary, pause/resume/revocation, axe and 320/360px reflow. The richer Northstar and upstream shop have automatic-observation journeys too.

Unit/HTTP tests cover one-use/expired/replaced pairing, token/Origin/Host checks, schema limits, transaction rollback before acknowledgement, session/clock replay, DB reopen and deduplication, deletion markers, retention and the 1,000-body bound. Test results and any remaining gates are recorded in [WORK.md](WORK.md).

The disposable Chromium test profile disables password saving and leak prompts for the shop's published synthetic login, using [Chromium's password-manager preferences](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/password_manager/core/common/password_manager_pref_names.h). Before this fixture change, waiting after login left page pointer/keyboard actions undelivered; with these test preferences the full observed checkout passes. The native popup itself was not captured. ReEntry does not change password-manager settings in the user's Chrome profile. Test assertions read the accepted store through the guarded HTTP endpoint; browser capture, permissions, actions and delivery remain real.

Native side-panel placement/shortcut behavior, external-site permission-dialog acceptance, VoiceOver and real browser zoom/text settings remain explicit manual gates. Automated tests exercise the same companion as an extension tab at side-panel width. No new real-model evaluation is claimed: model inputs/transports have not changed, and this phase does not call a model.
