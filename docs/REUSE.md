# Open-source reuse choices

Researched October 21, 2026. This is a source/API/license review, not proof that integrations pass in ReEntry. Phase 1 subsequently adopted WXT, its React/storage integrations, webext-core messaging, Dexie, Playwright, http-server and fake-indexeddb on October 22. Other shortlisted integrations remain planned; see [provenance](PROVENANCE.md). Pin tested versions and record copied files/commit ids when implementation starts.

## Recommended components

| Need                        | Reuse                                                                                                                           | License      | Integration and limit                                                                                                                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Extension scaffold/build    | [WXT](https://github.com/wxt-dev/wxt)                                                                                           | MIT          | Use its React/TypeScript scaffold in `extension/`; it supplies the build/dev workflow, not ReEntry capture behavior. Keep the Next.js starter for the web app.                                                        |
| Readable HTML content       | [Defuddle](https://github.com/kepano/defuddle) (`defuddle`)                                                                     | MIT          | Import the browser library into a user-invoked capture script. It returns cleaned content/metadata. Selection capture needs only the browser selection API; do not build a parser for it.                             |
| Internal extension messages | [webext-core messaging](https://github.com/aklinker1/webext-core) (`@webext-core/messaging`)                                    | MIT          | Typed request/reply between popup, content script, and worker; still requires our small message schema and handlers.                                                                                                  |
| Pending captures/settings   | [WXT storage](https://wxt.dev/guide/essentials/storage)                                                                         | MIT          | Reuse the storage wrapper; a saved pending capture survives popup/worker closure. It does not supply application acknowledgement or duplicate policy.                                                                 |
| Web app checkpoint database | [Dexie](https://github.com/dexie/Dexie.js) (`dexie`)                                                                            | Apache-2.0   | Use its IndexedDB schema/transaction APIs rather than writing a database wrapper from scratch. Revision/correction rules remain ReEntry logic. No Dexie Cloud service needed.                                         |
| Text differences            | [jsdiff](https://github.com/kpdecker/jsdiff) (`diff`)                                                                           | BSD-3-Clause | Use word/line differences for visible old/new text. It detects text edits, not whether a requirement changed; AI and user review provide interpretation.                                                              |
| Browser testing             | [Playwright](https://github.com/microsoft/playwright) (`@playwright/test`)                                                      | Apache-2.0   | Reuse persistent Chromium contexts, fixtures, routing, traces, and assertions. Test cases remain specific to ReEntry.                                                                                                 |
| Model/API test responses    | [MSW](https://github.com/mswjs/msw) + [Serve](https://github.com/mswjs/serve) (`msw`, `@msw/serve`)                             | MIT          | Shared request handlers for valid/invalid/slow responses. In-process MSW for unit/integration tests; Serve exposes the same handlers over HTTP for a separately running Next.js server. No custom mock server engine. |
| Local static test hosting   | [http-server](https://github.com/http-party/http-server)                                                                        | MIT          | Serve a small licensed fixture directory on another port; use loopback binding and disable caching for changed-source tests. No custom website backend or reset service.                                              |
| Accessibility checks        | [axe-core](https://github.com/dequelabs/axe-core) / [`@axe-core/playwright`](https://playwright.dev/docs/accessibility-testing) | MPL-2.0      | Run established rules against our UI; keep manual keyboard/VoiceOver checks. Use the package without modifying its engine and retain applicable notices.                                                              |

[WXT recommends existing messaging wrappers](https://wxt.dev/guide/essentials/messaging). For web app transfer, use [Chrome's website messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging#send-messages-from-web-pages) with an explicit [externally-connectable allowlist](https://developer.chrome.com/docs/extensions/reference/manifest/externally-connectable). The app requests a pending capture and receives the reply; do not assume the extension can initiate a message to an arbitrary web page. This removes the earlier proposed custom HTTP queue. IDs, sender checks, acknowledgement, and deduplication still need a small adapter.

## Capture alternatives examined

| Option                                                                                                 | What is already available                                                                       | Decision                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Mozilla Readability](https://github.com/mozilla/readability)                                          | Apache-2.0; standalone article extraction package `@mozilla/readability`                        | First alternative if Defuddle fails our instruction-page examples. Choose one extractor after a spike rather than installing two by default. Neither understands application completion or every website.                                                                                                                                              |
| [Obsidian Web Clipper](https://github.com/obsidianmd/obsidian-clipper)                                 | MIT source for an installable clipping/highlighting extension; its extraction uses Defuddle     | Useful ready-made capture tool and implementation reference. Its installed workflow saves to Obsidian, not ReEntry; no verified generic ReEntry destination. Forking needs destination/permissions/UI changes and upstream attribution, so a fork is not a zero-effort plug-in. Reuse Defuddle first. Brand assets are excluded from its code license. |
| [Clipper programmatic API source](https://github.com/obsidianmd/obsidian-clipper/blob/main/src/api.ts) | Source `clip()` API with template processing; caller supplies HTML, parser, and output handling | A source-based alternative if we need templates. Although repository exports include an API build, `obsidian-clipper` was not found on the npm registry during this review; do not prescribe `pnpm add obsidian-clipper` as a verified installation. Source packaging and bridge work would remain.                                                    |
| [PDF.js](https://github.com/mozilla/pdf.js) (`pdfjs-dist`)                                             | Apache-2.0; PDF rendering/text APIs                                                             | Use if PDF import is added later. It is not OCR for image-only scans and does not grant access to arbitrary browser PDF tabs. Not required for the HTML hackathon journey.                                                                                                                                                                             |
| [Mammoth](https://github.com/mwilliamson/mammoth.js) (`mammoth`)                                       | BSD-2-Clause; DOCX content extraction                                                           | Use for an explicit DOCX import feature later. Layout fidelity, file permissions, and safe presentation still need handling. Do not build a DOCX parser.                                                                                                                                                                                               |

Defuddle's browser API accepts the current document and returns cleaned content/title. Its core bundle avoids the extra Markdown/math dependencies of the full bundle. For our local workflow, disable optional asynchronous/remote extractors, preview what was extracted, and preserve raw selected text as evidence. If selection is already sufficient, skip article extraction entirely. Article cleanup can omit short requirements, so test it rather than assuming it captures every instruction.

## Model client reuse

October 22 decision: use a [small provider-independent harness](HARNESS.md), not LangChain/LangGraph. Local Ollama is the first adapter. For later hosted adapters, reuse [AI SDK Core's unified provider interface](https://ai-sdk.dev/docs/foundations/providers-and-models) with direct [OpenAI](https://ai-sdk.dev/providers/ai-sdk-providers/openai) or [DeepSeek](https://ai-sdk.dev/providers/ai-sdk-providers/deepseek) packages behind ReEntry's own small interface. No gateway service is required. Keep provider-specific options outside recovery logic and validate every proposal in ReEntry. Install and pin only the clients needed by the working slice; no AI SDK/provider package was installed during this planning revision. Future adapters need their own envelope/capability tests and live evaluation before claiming support.

## Existing online sandboxes

| Ready-to-use site                                                        | Primary source/license                                                                               | Use in ReEntry testing                                                                                                                                                                                                                                              | Limit                                                                                                                                                 |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Selenium web form](https://www.selenium.dev/selenium/web/web-form.html) | [Source](https://github.com/SeleniumHQ/selenium/blob/trunk/common/src/web/web-form.html), Apache-2.0 | Open a real external form; test capture of visible text, save work URL, and reopen it; use synthetic inputs only                                                                                                                                                    | Generic test form, not a scholarship system; persistent form progress and instruction version control are not promised.                               |
| [The Internet](https://the-internet.herokuapp.com/)                      | [Source](https://github.com/saucelabs/the-internet), Apache-2.0                                      | Existing [dynamic loading](https://the-internet.herokuapp.com/dynamic_loading), [frames](https://the-internet.herokuapp.com/frames), [login](https://the-internet.herokuapp.com/login), and [status code](https://the-internet.herokuapp.com/status_codes) examples | Great smoke-test coverage, not a deterministic semantic requirement-change fixture. A frames example alone does not establish cross-origin isolation. |

Both public sites loaded during research. Use them for low-volume manual smoke tests with synthetic data, not as mandatory CI dependencies. Public sites may change or be unavailable; do not try to modify their published content. The Internet can run locally from upstream using its documented Ruby/Docker setup, but that is optional overhead, not a required service.

For deterministic tests, pin only the needed upstream HTML/assets in a local fixture directory with licenses. Selenium's form references external CDN resources and a submission target: cache/replace only necessary assets or test without decorative assets, remove/disable submissions in the local derivative, record modifications, and verify the offline fixture. Do not claim a downloaded page is self-contained without checking its dependencies.

## What still needs a small custom fixture

The reviewed public sandboxes do not provide a controllable “one referee → two referees” instruction pair with a stable source URL and reset. Implement only that missing content:

- A short fictional instruction document in V1 and V2, plus a few error/contradiction variants. It may sit beside a reused sample form; no scholarship backend or account system.
- Serve the directory with `http-server`; a test fixture copies the selected version to one stable `instructions.html` in a temporary per-run directory. Reset by restoring the baseline, not by building an admin UI.
- Use Playwright `route.fulfill`/`route.abort` for additional page/API failures. Browser routing does not intercept Next.js server-to-Ollama calls: use MSW in that process or Serve at a configured model URL for those.
- A few MSW response definitions for model shape/errors and a browser test harness. These are test data/adapters, not new testing frameworks.

## Source and package verification

Checked upstream READMEs/APIs and GitHub license metadata. Registry package names/repositories and versions were also checked. Observed versions include WXT 0.21.4, Defuddle 0.19.5, messaging 4.0.0, Dexie 4.4.6, diff 9.0.0, MSW 3.0.3, Serve 0.11.0, http-server 14.1.1, and axe Playwright 4.14.0. These are research observations, not a committed dependency set or a compatibility guarantee. Use each installed version's docs; newer major versions can change import paths.

The old `mswjs/http-middleware` repository redirects to `mswjs/serve`. The current package documented upstream is `@msw/serve`; avoid copying stale installation instructions. Server-side mocks need to match the actual Ollama adapter response shape, not just the inner model JSON.

Before adopting: run the smallest import/build/capture test on pinned Node 22.23.2, pin the working package version in the lockfile, retain licenses/notices for copied fixtures/code, and update [provenance](PROVENANCE.md). ReEntry-specific recovery behavior must remain clearly distinguished from upstream functionality in submissions.
